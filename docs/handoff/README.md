# 活動、簽到及抽獎系統交接

目前需求版本：**v1.1**（2026-10-23）。對象：產品負責人、研發、測試及研發使用的 AI。

## 閱讀順序

**優先閱讀：[v1.1 完整 PRD](versions/v1.1/PRD.md)**。一份文件涵蓋全部規格、流程、驗收及實作交接。以下為同版分拆源文件，內容與 PRD 同步維護。

1. [功能需求與驗收規格](versions/v1.1/SPEC.md)：最終業務規則、欄位、各端互動及驗收條件。
2. [正式系統實作交接](versions/v1.1/IMPLEMENTATION.md)：資料關係、服務責任、演示差異、代碼定位及 AI 開發約束。
歷史確認紀錄僅供維護追溯；最終規則已合併進 PRD，研發不需要再整理討論紀錄。

## 文件效力

- 本文件集記錄產品方案，不代表正式後端已實現。
- 用戶最新確認 > 本文件已確認規則 > 演示代碼。出現矛盾須報告，不能默默選擇代碼行為。
- 「已確認」表示用戶直接決策；「演示基線」表示保留目前演示中未要求更改的可見流程；「技術要求」表示使已確認行為可用的實作約束，並非指定技術棧。
- 待確認項不可擅自補齊；涉及範圍變更先詢問產品負責人。
- 本次只交付文件，不修改演示業務代碼，不提交或部署。

## 範圍

包含活動基本配置、簽到管理、名單／分枱／座位、邀請函、電郵、APP 活動、抽獎管理、抽獎大屏及相關統計。投票僅保留活動關聯與入口，不包含完整投票規則；一般訪客、保安門禁及考勤不在此範圍，僅涵蓋活動二維碼核銷接點。

## 如何使用

研發先逐條閱讀 SPEC，對照 IMPLEMENTATION 的演示差異；以需求編號作為任務及測試標識。先完成名單、身份、時間及持久化，再接通報名／邀請函／簽到，最後實作抽獎狀態同步及寄信排程。每次交付列出已完成的需求編號、測試結果及尚未完成項。

演示：從專案根目錄安裝依賴後，以 `npm run dev` 啟動；預設 http://127.0.0.1:3000/。瀏覽器本機儲存中的示例不是正式資料。

## 版本與 GitHub 交付

[版本索引及更新規則](VERSIONS.md)。每一版包含完整規格、實作交接、決策紀錄及相對上一版的變更摘要。

提交及推送時，請將本目錄與對應演示代碼一起納入同一次提交。研發取得該提交後即可閱讀，不需要另下載 ZIP。僅 Commit 尚未上傳 GitHub，必須 Push；私人倉庫還需授予研發存取權限。

文檔需求版本不等於系統已上線版本。v1.1 的同次提交代碼仍是演示，必須按實作差異清單補齊正式能力。此版文件尚未對應遠端發布標籤，不應假稱已上線。
