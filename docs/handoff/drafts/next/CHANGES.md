### APP 組合示例（2026-10-28）

原「新春盆菜宴」內容及流程保持不變。原「新春盆菜宴（已結束）」由三個進行中示例替換，排列在原示例之後：

| 示例 | 展示方式 |
| --- | --- |
| 新春盆菜宴（簽到＋多抽獎） | 一個簽到項目及兩個獨立抽獎項目；顯示簽到活動／抽獎活動頁籤，抽獎可依場次查看，各項目有獨立名稱、獎品及結果。 |
| 新春盆菜宴（僅簽到） | 直接展示報名、邀請函及簽到內容，不展示抽獎頁籤或單一頁籤切換列。 |
| 新春盆菜宴（僅抽獎） | 直接展示抽獎項目、個人結果及公布名單，不展示簽到、報名、邀請函及簽到場次選擇。 |

三個示例使用獨立演示身份及抽獎資料，不新增 CMS 活動或改寫 CMS 原始名單。進入示例時重設演示狀態；保留簽到未報名／報名成功／未分配枱號及座位號／已簽到，以及抽獎未開始／抽獎中／已得獎／未得獎切換。

參與規則修訂：同一員工可參加同一活動下的多個簽到項目，但每個簽到項目只能參加一個場次。各項目的名額、邀請函、簽到記錄獨立計算；取代舊版以整個活動限制只能參加一場的描述。本次三個示例不包含多簽到項目列表，該組合介面仍待實作。

### 活動關聯管理責任（2026-10-29 最終確認）

關聯簽到由「簽到管理 → 來源活動」控制；關聯抽獎由「抽獎管理 → 來源活動」控制。活動管理只展示「活動關聯」表格，不提供關聯選擇、新增／刪除項目、項目名稱編輯或排序操作。調整或清除來源活動後，重新進入活動管理即可顯示更新後關聯，不得用過時的 projects 或 modules 還原已解除關聯。

表格欄位為關聯簽到、關聯抽獎。同屬本活動的抽獎按其來源簽到歸組：同一簽到可顯示多個抽獎；沒有抽獎的簽到獨立列；未連接本活動簽到的抽獎獨立列。抽獎來源場次與參與名單仍由抽獎管理控制，不因活動表格顯示而改寫。

以上取代先前「活動項目配置」由活動管理編輯關聯、名稱及排序的方案。保留已建立的示例資源，活動端不刪除簽到或抽獎實體。
