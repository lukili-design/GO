## 更新規則

1. 每次產品版本更新建立獨立版本目錄，保留上一版，不直接覆蓋已交付版本。
2. 每版保存完整的 SPEC、IMPLEMENTATION、DECISIONS，另加 CHANGES 列明新增、修改、移除、受影響需求編號、驗收及遷移影響；研發不必拼接多版文件才得到當前需求。
3. 一般功能迭代用 v1.1、v1.2；僅文案澄清可用 v1.0.1；重大流程或不相容規則變更用 v2.0。若專案已定版本號，以產品指定版本為準，勿另造一套衝突編號。
4. 新版需求未確認時標示草稿，不切換首頁的目前交接版本；確認後更新本索引及首頁連結。
5. 需求編號維持穩定；刪除的需求記錄為停用，不將編號重新分配給其他功能。語義變更列出前後差異。
6. 文檔、對應演示代碼及修改記錄一起提交並推送。用包含該版文檔的提交追蹤代碼基線；若另行建立 Git tag，需由用戶明確授權，不自動提交／打標籤／發布。
7. 版本文件只證明需求與代碼基線，不代表完成研發、測試或部署。正式完成狀態由研發另外報告。
8. ZIP 僅為分享副本，GitHub 內版本文件才是維護來源。更新版本後重新匯出 ZIP，不沿用舊壓縮包。

9. 從 v1.1 起每版提供完整 PRD 閱讀版，由同版三份詳細文件合併；修改詳細源文件後必須同步生成 PRD，避免兩套規則。
